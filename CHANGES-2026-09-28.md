# Cintexa Nexus CMS: fixes & upgrades (28 Sep 2026)

## Root causes found
1. **Frontend called an unauthenticated API with plain `fetch()`**. Most pages never sent the Firebase token. Fixed with `installAuthFetch()` (`src/lib/api.ts`) + a real auth guard on the API (`apiGuard`).
2. **Silent save failures**: Drizzle `.set()` ignores snake_case keys. Media alt/caption, SEO settings, Site colour/updatedAt, Post category/SEO/image/reading-time and Plugin updates were all being dropped. All rewritten with the schema's property names.
3. **Database tables missing on fresh databases** (`relation ... does not exist`). Intake share links, Sites, Media, etc. Added idempotent `ensureSchema()` (`lib/db/src/bootstrap.ts`) that runs on API boot and before intake calls, plus `platform_settings`.
4. **Share links pointed at the API host** (`localhost:8080`) instead of the app. The link is now always built from the browser origin (`buildShareUrl`) with `PUBLIC_APP_URL` as server fallback.
5. **JSON body limit (100 kB)** made Media uploads fail with 413. Now 25 MB (`JSON_BODY_LIMIT`).
6. **Pipeline only returned scheduled items**, so unscheduled drafts could never be dragged onto a week. It now returns drafts too; UI gained a draggable Backlog.
7. **Calendar excluded the last day** of the range (bare date = midnight). Fixed with whole-day + timezone slack.
8. **Sites**: status badge compared `"Active"` to `"active"` (never matched); Settings button did nothing.
9. **Settings**: API keys/webhooks were stubs that stored nothing real. Rebuilt (below).

## Feature work (nothing removed, everything rebuilt or extended)
- **Diagnostics → Intake share link**: create / copy / native share / WhatsApp / e-mail / QR (downloadable) / expiry / pause / delete / submission counts / latest submissions; public form has honeypot + rate-limit + size limit; `intake.submitted` webhook.
- **Sites**: edit, pause/activate, delete (local fallback kept).
- **Pages/Posts**: publish fires `content.published`; scheduler too.
- **Calendar / Pipeline**: fixed as above; backlog drag-and-drop, drop-to-unschedule.
- **Media**: drag & drop, multi-upload with progress, 8 MB guard, image dimensions, grid/list, search/filter, edit alt+caption, copy URL, download, delete.
- **Taxonomy**: categories edit/delete/search/slug validation + Tags tab.
- **Menus**: visual builder with sub-items, reorder, add-from-pages, JSON tab, duplicate, edit, delete.
- **Forms**: edit, delete, embed-code generator, public endpoint `/api/public/forms/:id/submissions`, CSV export, delete submissions, `form.submitted` webhook.
- **SEO**: robots.txt accepts a directive or a full file, sitemap escaping/base URL, redirect add/delete with validation (301/302/307/308, no duplicates), SERP preview, OG image.
- **Settings**: 
  - *Appearance*: theme (live OS follow), 7 accents + **custom colour picker**, corner style, reduce-motion, live preview, reset.
  - *API keys*: `cxk_…` keys, SHA-256 hashed at rest, shown once, read/write scope, expiry, last-used, revoke; accepted via `Authorization: Bearer` or `x-api-key`; never allowed on Settings/Users.
  - *Webhooks*: HMAC-SHA256 signed (`x-cintexa-signature`), events picker, enable/disable, test ping, delivery log, auto-pause after 10 failures, SSRF protection.
  - *Security*: password min length, session timeout, IP allow-list (CIDR; refuses lock-out; `DISABLE_IP_ALLOWLIST=1` escape hatch), per-client rate limit, password change wired to Firebase re-auth.
- **API security**: global `apiGuard` (public allow-list only for intake public form, public forms, settings/public, robots/sitemap, health), admin-only Settings writes, `ADMIN_EMAILS`.
- **Cloudflare Pages function**: forwards host headers, healthz + public-settings stubs, clearer 503 hint.

## Verified
`tsc` clean (api-server + cintexa), `vite build` OK, and an end-to-end run on real PostgreSQL 16: intake link → public submit → import, API key scopes (401/403/204), IP allow-list lock-out guard, signed webhook delivery (signature validated) + log, sites/media/posts/categories/menus/forms/SEO/redirects/pipeline/calendar/scheduling.

## Deploy (Cloudflare Pages)
The web app is static; **Content, Media, Forms, SEO, API keys, webhooks and share links need the Express API running somewhere** (Render, Railway, Fly, a VPS…). Then in Cloudflare Pages → Settings → Environment variables set `API_ORIGIN=https://your-api-host` (no `/api`). See `artifacts/api-server/.env.example`.
