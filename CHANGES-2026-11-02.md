# 2026-11-02 - Settings keys rejected (401) / open access mode

**Root cause.** The web app sends no credentials (`artifacts/cintexa/src/lib/api.ts`: "There is no sign-in"), but `apiGuard` /
`requireAdmin` in the API server required a Firebase token, JWT or `cxk_` key on every non-public route. Every Settings call
(save OpenRouter key, create/list API keys, security, webhooks) therefore returned `401 Authentication required`, which the UI
reported as a rejected key whatever the key was.

**Changes**
- `lib/auth-middleware.ts`: new `AUTH_MODE` (`open` default | `enforced`). In `open` mode a request with no valid credential is served
  as an implicit admin (`sub: "open-access"`, e-mail from `OPEN_ACCESS_EMAIL`). Real Firebase tokens / JWTs / `cxk_` keys are still
  honoured when sent, including the read-only/write scope rules. Rate limiting for the open identity is per client IP.
- `routes/settings.ts`: "Test key" called `GET /models`, which OpenRouter serves without authentication, so it reported any key as
  valid. It now calls `GET /auth/key`, which really validates the key.

**Security note.** In `open` mode anyone who can reach the API can read/change Settings, mint `cxk_` keys and use all admin routes.
Run it only on localhost / a private network, or set `AUTH_MODE=enforced` (and `ADMIN_EMAILS`) before exposing it publicly.

**Not verified here.** No build, typecheck or tests were run for this change. Sales, Finance and CCDI have their own RBAC layers that
may still refuse the open-access identity; check them after deploying.
